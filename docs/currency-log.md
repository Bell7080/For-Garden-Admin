# 재화 기록 (획득·소모 감시)

계정 상세(계정 → 계정 선택)의 「재화 기록」 카드가 왼쪽 **획득**, 오른쪽 **소모** 두 열로 보여 준다.
각 줄: 재화 · 증감 · 직후 잔액 · 출처(게임 호출 이름) · 시각. 위에는 최근 7일 출처별 합계와 큰 수량 건수, 재화 필터, 「이상 징후만」 토글이 있다.

## 어떻게 기록되나
- 게임 지갑의 진짜 잔액은 `player_saves.data.wallet`이고 모든 호출은 `server_commit_state`로 확정된다.
- 마이그레이션 `20261031000000_currency_log.sql`이 `player_saves`에 트리거를 달아 **지갑 앞뒤 차이**를 `currency_log`에 쓴다. 출처는 껍데기가 넘기는 호출 이름이다.
- 어드민 조정은 우편·조회 호출 안에서 함께 반영돼도 `admin_adjust`로 갈라 적는다. 결투 상대처럼 호출자가 아닌 계정이 바뀌면 `other:<호출>`.
- 스테미나는 시간으로도 차므로 소모와 충전·보상 계열 호출의 증가만 남긴다.
- 범위는 지갑 재화다. 가방 아이템은 2단계.

## 이상 징후 기준
`currency_alert_rules`(재화별 `big_delta` = 한 번에 이 값 이상, `burst_10m` = 10분 합계 이 값 이상). 초기값은 추정치이므로 운영하며 SQL로 고친다.
기준을 넘은 줄에 「큰 수량」「단시간 급증」 표시가 붙는다.

## 운영
- 적용: 운영 DB에 사람이 SQL을 적용한다(게임 저장소에도 같은 파일이 있다). 적용 전에는 카드가 안내 문구만 보여 준다.
- 보관: 수동 정리 `select public.server_prune_currency_log(180)` (서비스 롤).
- 읽기 권한: owner/operator/cs. 표 자체는 클라이언트가 직접 읽지 못하고 `admin_currency_log` 함수만 통한다.
- 2단계 후보: 전 계정 대상 최근 급증 순위 화면, 아이템 증감.
