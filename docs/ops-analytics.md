# 행동·결제 퍼널 (admin_analytics)

대시보드 아래 「퍼널 (최근 30일 가입)」 카드가 한 함수(`admin_analytics`)를 읽는다. 모든 운영진이 본다(읽기 전용).

## 적용 순서

2026-11-11 QA·운영 적용을 확인했다. [실제 이력과 검증](migrations-2026-11-11.md)을 참고한다.

1. 게임 저장소 `supabase/migrations/20261122000000_game_events.sql` — 저장이 바뀔 때 튜토리얼 칸·관문 첫 클리어·연구원 레벨·연구 횟수를
   `game_events`에, 상태를 바꾼 호출 수를 `game_call_daily`(하루 × 호출 이름)에 남긴다. 게임 코드는 바뀌지 않고, 기록이 실패해도 저장은 막지 않는다.
2. 이 저장소 `supabase/migrations/20261122100000_ops_analytics.sql`.

둘 다 적용하기 전에는 카드에 적용 안내만 선다. 1만 빠져도 퍼널·잔존·이탈 관문·첫 결제는 보이고(저장과 `purchase_records`에서 읽는다) 호출 수·연구 횟수만 빈다.

## 무엇을 세나

| 줄 | 근거 |
|---|---|
| 퍼널 | 최근 N일 가입(삭제 제외) 중 지금 저장에 튜토리얼 마지막 칸(`pull`)·`1-5`·`1-10`·`2-10`이 있는 수, 환불 안 된 결제가 있는 수 |
| 잔존 D1·D7·D30 | 가입일 + N일에 `player_daily_activity`가 있는 비율. 그날이 아직 오지 않은 가입자는 분모에서 뺀다 |
| 떠난 계정의 마지막 관문 | 3일 넘게 접속 없는 가입자의 가장 앞선 본편 관문(`장-번호`만, 곁가지·난이도 키 제외) |
| 첫 결제 상품 | 계정마다 가장 이른 결제 한 건의 상품 |
| 최근 7일 호출 수 | `game_call_daily` 상위 20 |

튜토리얼 칸이 늘면 함수의 `last_step` 한 값을 고친다. 출시 전 초기화 목록에는 게임 저장소가 `game_events`·`game_call_daily`를 reset으로 분류해 두었다.
