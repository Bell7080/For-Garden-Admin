# 공지 원고 운영

자동 번역 API, 번역 생성·재시도 버튼, 번역 캐시 조회와 외부 서비스 설정을 제거했다. 별도 번역 서버나 Azure/Gemini 키를 연결하지 않는다.

어드민에서는 원문 제목·본문을 필수로 작성한다. 다른 언어의 제목·본문은 선택 입력이다. 홈페이지는 사이트 선택 언어의 직접 작성한 원고가 있으면 표시하고, 없으면 원문을 그대로 표시한다. 원문의 실제 언어를 `lang` 속성으로 전달하며 브라우저의 번역 기능을 막지 않는다. 원문 언어는 표시하지만 미완료·번역 대기·서버 연결 경고는 표시하지 않는다.

원문·게시 설정·수동 원고의 원자적 저장과 동시 편집 보호에는 `supabase/migrations/20261017090000_notice_editor.sql`을 사용한다. 홈페이지 기본 스키마와 게임의 `20261015180000_notice_admin.sql`이 선행되어야 한다. 동일 Supabase DB이므로 두 저장소의 사본 중 하나만 적용한다. 운영 DB에 이 SQL을 원격 적용하지는 않았다.

DB에 저장 RPC가 아직 없으면 정확한 PGRST202 오류에서만 기존 한국어·영어·일본어 저장을 유지한다. 이 호환 저장은 원자적 저장과 동시 편집 보호가 없으며 화면에 제한을 안내한다. 조회는 번역용 테이블·RPC를 요구하지 않는다.

기존 `20261016090000_notice_translation.sql`과 `20261016210000_translation_budget.sql`은 과거 마이그레이션 이력이다. 신규 설치를 위해 실행하지 않는다. 이미 적용된 DB의 자동 생성 결과·사용량 테이블은 이번 코드 변경으로 삭제하지 않았고, 현재 애플리케이션은 이를 읽거나 쓰지 않는다. 원고 및 운영 데이터를 보존하며 기존 수동 원고 테이블은 그대로 사용한다.

Vercel에 번역용 환경 변수를 등록했다면 두 프로젝트에서 `TRANSLATION_*`와 `AZURE_TRANSLATOR_*`를 삭제할 수 있다. 현재 코드는 사용하지 않는다. Web의 공지·사전예약용 Supabase 서버 설정은 유지하고, Admin은 기존 Supabase 사용자 인증·RLS를 그대로 사용한다. 외부 클라우드 리소스 해지나 운영 DB 삭제는 수행하지 않았다.
