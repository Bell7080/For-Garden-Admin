# 운영 콘솔 v4 (2026-11-06)

v3의 「다음 후보」 중 지금 만들 수 있는 셋 — 조건별 대상 우편, 이상 징후 알림, 계정이 받은 신고.
푸시 알림(네이티브 앱 필요)과 스토어 환불 웹훅(실결제 필요)은 보류한다.

## 적용 순서 (운영 DB 미적용)

v3가 먼저다.

1. 게임 `For-Garden/supabase/migrations/20261120000000_ops_moderation.sql`
2. 이 저장소 `20261120100000_ops_console_v3.sql`
3. 이 저장소 `20261121000000_ops_console_v4.sql`

적용 전에는 새 화면·카드가 "DB 업데이트가 필요합니다" 안내만 띄운다. 게임 코드는 바꾸지 않아도 된다(대상 우편은 기존 `target_player` 우편이다).

## 새로 생긴 것

| 화면 | 권한 | 하는 일 |
| --- | --- | --- |
| 우편 작성 · 조건으로 보내기 | 소유자·운영자 | 레벨 범위 · 최근 N일 안 접속 · N일 넘게 미접속 · 가입일 범위로 골라 한 명씩 대상 우편. 정지 계정 포함은 선택, 영구 제한·삭제 계정은 늘 빠진다. 보내기 전 미리보기(인원 + 표본 8명)와 확인 필수, 한 번에 50,000명까지. 감사 로그에 조건이 남는다 |
| 이상 징후 | 전원 열람, 확인은 소유자·운영자·CS, 문턱은 소유자 | 하루(KST, 오늘·어제) 재화 획득 급증 · 48시간 안 큰 수동 조정 · 새 오류 확산 · 오류 폭증 · 하루 환불 급증. 계정·오류·결제 화면으로 바로 이동. 확인 메모를 남기면 목록에서 숨는다(「확인한 것도 보기」로 다시 본다) |
| 대시보드 | — | 할 일 목록에 확인 안 한 이상 징후 수 |
| 계정 상세 · 받은 신고 | 전원 | 지운 신고를 뺀 받은 신고 수 · 처리 안 된 수 · 신고한 사람 수 · 최근 5건 |

게임 쪽 신고 입력은 v0.407.0에 들어갔다 — 친구·길드원 프로필 카드의 UID 줄 「신고」가 신고 분류로 문의 창을 열고 `reported_uid`를 싣는다.

### 이상 징후 기본 문턱

`ops_anomaly_rules`에 들어 있고 소유자가 화면에서 바꾼다(감사 로그 `anomaly_rule`).

| 키 | 기본값 |
| --- | --- |
| `gain:gems` / `gain:gold` / `gain:cheesecake` | 50,000 / 3,000,000 / 200,000 |
| `gain:amber` / `gain:fossil` / `gain:rawStone` | 100 / 100 / 30,000 |
| `gain:dnaFragments` / `gain:duelEmblem` / `gain:raidSigil` / `gain:salvageRecord` / `gain:stamina` | 500 / 2,000 / 1,000 / 5,000 / 10,000 |
| `error:new_players` | 처음 본 지 24시간 안에 영향 계정 3명 이상 |
| `error:hot_occurrences` | 최근 1시간 안에 다시 난, 누적 500회 이상 오류 |
| `refund:day` | 최근 24시간 환불 5건 이상 |

수동 조정은 재화별 획득 문턱을 그대로 쓴다.
