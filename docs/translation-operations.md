# 공지 자동 번역 운영

현재 코드가 다루는 것은 공지입니다. 향후 게시판은 게시글 테이블·권한 확인을 별도로 만들고 같은 번역 모듈의 원문 → 언어 → 해시 캐시 방식을 재사용합니다. 아직 게시판이나 문의 접수를 운영 중인 것으로 표시하지 않습니다.

## 무료라는 말의 범위

스텔라크래프트(`stellarcraft.biz`)의 번역 사업자는 이 환경에서 접속 정책상 확인하지 못했습니다. 같은 사업자를 사용한다고 주장하지 않습니다.

기본 구현은 [LibreTranslate](https://github.com/LibreTranslate/LibreTranslate)의 `GET /languages`, `POST /translate` 규약입니다. OpenAI·DeepL 등 유료 API를 자동으로 선택하거나 키 없이 무료라고 가장하지 않습니다. LibreTranslate는 자체 운영 가능한 AGPL-3.0 소프트웨어입니다. 상업적 사용은 가능하지만 라이선스 의무가 있으며, 서버·메모리·CPU 비용은 별도입니다. 사용하는 Argos 언어 모델의 라이선스와 지원 언어 조합도 배포 전에 확인해야 합니다. 무료 공개 인스턴스를 무제한 사용 가능한 서비스로 취급하지 않습니다.

한국어 원문 + 번역 대상 11개: en, ja, zh-Hant, zh-Hans, th, vi, id, es, pt-BR, de, ru. 원문은 다른 언어로 지정해도 됩니다. **LibreTranslate를 설치했다는 이유만으로 이 모든 조합이 지원되는 것은 아닙니다.** 각 요청에서 `/languages`의 source/targets를 확인하고, 미지원 조합은 성공으로 저장하지 않습니다. 서버가 `pt` 같은 다른 코드를 쓰면 검증한 경우에만 `TRANSLATION_LANGUAGE_MAP`에 명시합니다. 중국어 간체/번체를 `zh` 하나로 조용히 합치지 않습니다. 양쪽 지원 또는 명시적인 문자 변환을 갖춘 서버가 필요합니다.

## 배포 순서

1. 홈페이지 기본 스키마와 게임의 `20261015180000_notice_admin.sql`이 적용된 Supabase 프로젝트에 `20261016090000_notice_translation.sql`을 한 번 적용합니다. 같은 파일을 두 저장소에 보관했지만 두 번 적용하지 않습니다. 기존 게임 테이블은 수정하지 않습니다.
2. 자체 번역 엔진을 장기 실행 가능한 서버에 준비하고 HTTPS·접근 인증·사용 모델을 확인합니다. Vercel의 짧은 서버 함수에서 번역 모델을 직접 실행하지 않습니다.
3. **Web와 Admin 두 Vercel 프로젝트**에 서버 전용 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TRANSLATION_API_URL`을 설정합니다. 번역 엔진이 요구하면 `TRANSLATION_API_KEY`도 설정합니다. 이 값은 브라우저 번들이나 Git에 넣지 않습니다. Admin의 기존 publishable key는 로그인용 공개 키이며 service_role을 대신할 수 없습니다.
4. 어드민에서 원문만 작성해 저장합니다. 원문 + 게시 설정 + 직접 쓴 번역은 RPC의 단일 트랜잭션으로 저장됩니다. 다른 창에서 수정한 글은 `stale_notice`로 충돌을 알리고 덮어쓰지 않습니다.
5. 저장 뒤 브라우저에서 번역을 두 건씩 준비합니다. 화면을 닫으면 남은 작업이 모두 실행된다고 보장하지 않습니다. 이때도 원문 저장은 완료되며, 읽는 시점의 번역이 누락분을 보완합니다. 미완료 사유·현황과 재시도 버튼을 제공합니다.
6. 독자가 공지 읽기 언어를 선택하면 목록은 직접 번역/최신 자동 번역/원문 순으로 표시합니다. 번역이 없는 글을 열면 그 언어를 요청하고 저장합니다. 아직 준비되지 않았거나 실패하면 **원문 언어를 표시**합니다. 원문은 즉시 읽을 수 있고 번역을 기다리며 글 전체를 가리지 않습니다.

## 캐시·권한·운영 특성

- 자동 번역은 `website_notice_auto_translations`에 저장하고 직접 작성한 언어는 `website_notice_translations`에 보관합니다. 직접 작성한 번역이 항상 우선합니다.
- 원문 언어·제목·요약·본문의 SHA-256이 일치해야 자동 번역을 사용합니다. 원문 수정 시 낡은 번역은 조회 단계에서 제외하고 다음 저장/열람에서 재생성합니다. 직접 작성한 번역은 운영자가 검수해 관리합니다.
- 공개 번역 API는 slug와 언어만 받습니다. 임의 텍스트·외부 URL·임시저장·미래 예약 공지를 번역할 수 없습니다. 어드민 번역 API는 Supabase 사용자 검증 뒤 owner/operator 역할만 허용합니다. cs/viewer는 읽기 전용입니다.
- 브라우저의 토큰은 기존처럼 메모리에만 둡니다. 서버 전용 키는 서버 함수에서만 사용합니다.
- 엔진 호출은 메모리 내 중복 합치기와 Postgres의 인스턴스 간 lease로 중복 실행을 줄입니다. 전체 동시 작업은 4개로 제한해 자체 서버를 보호하며 **일일 번역량 한도를 부과하지 않습니다**. lease는 만료/해제됩니다.
- 이미지 URL·마크다운 구조·빈 줄은 번역하지 않고 텍스트만 전달합니다. 반환값의 타입·개수·길이를 확인하고 HTML로 신뢰하지 않습니다. 제목·본문 렌더링은 항상 escape합니다.
- 45초 요청 기한, 60초 서버 함수 상한을 사용합니다. 긴 글은 번역 서버 성능에 따라 실패할 수 있으며 원문 폴백을 유지합니다.
- API/DB가 준비되지 않은 상태에서 실제 자동 번역이 켜졌다고 안내하지 않습니다. 현재 클라우드에는 번역 서버·Supabase 쓰기 권한 바인딩이 없으므로 실제 운영 DB 적용과 외부 번역 성공은 검증하지 못했습니다. 자동화 검증은 모의 엔진과 Postgres WASM 엔진을 사용합니다.

## 기존 어드민 호환

운영 DB에 RPC가 아직 없을 때의 정확한 `PGRST202` 오류에만 기존 3개 언어 저장을 유지합니다. 일반적인 네트워크·권한·충돌 오류에서는 이 경로로 우회하지 않습니다. 추가 언어는 이 모드에서 저장할 수 없습니다. 기존 방식은 단일 트랜잭션이 아니므로 제한을 화면에 표시하고, 신규 공지는 원문 저장 후에 공개합니다. 기존 글 저장 실패 시 이전 수동 원고 복원을 시도하되 성공을 보장하지 않으며 실패 사실을 알립니다. 마이그레이션을 적용하면 자동으로 RPC 경로를 사용합니다.
